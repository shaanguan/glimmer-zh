Lists are containers of elements with built-in scrolling and focus.
Principles
Clear Organization
: Lists should present information in a clear
scannable vertical arrangement.
Consistent Item Presentation
: List items should follow a consistent visual
structure.
Focusability & Navigation
: In interfaces relying on directional navigation,
lists must clearly indicate the focused item.
Interactivity
: List items often represent selectable or actionable elements.
Usage & Placement
Lists can contain various sibling content with repeatable elements. Unlike
stacks, lists fill the app view container.
Lists can show one or more selectable items within a view.
Use scrims to indicate overflow content
When a list contains more items than will fit within a view, a black scrim is
used near the list's bounds.
Lists can use a title if necessary
A static or sticky title can be used in a list for clarity.
Don't
Have more than one list per view, this is overwhelming visually and focus wise.
Use depth to indicate focus
List items move between 0 and +4 depth for unfocused and focused states.
List items can be actionable
Items in a list can act as actions. Keep the action to the list item
Highlight the control that will be activated on tap, even if you can scroll
something else. If a list or card can be scrolled behind another element,
only focus the item that responds to tap.
Do
Only highlight the currently focused element, This allows users to discover focusable controls.
Don't
Highlight multiple focusable UI elements as this is confusing what is linked to tap input.
Anatomy
List is composed of a scrolling container and consistently spaced list items.
Lists should vertically scroll, with minimal overshoot, when the number of items
exceeds the viewport.
